## 发现并修复的问题（严重）

### BUG-1 / BUG-2：前置实体为 null 仍进入 Save → 空引用异常（500）
- **位置**：`PmsBomController` Create/Edit POST（共 2 处）、`GoodsApplyController` Create/Edit POST（共 2 处）。
- **根因**：原代码先 `if (step/worker == null) ModelState.AddModelError(...)`，再用
  `if (step/worker != null && !ValidateXxx(...))` 决定是否返回视图。
  当 `step/worker` 为 null 时**绕过了校验分支**，继续走到 `SaveBom/SaveBill` 并解引用
  `step.FItemID` / `worker.DEPID` → `NullReferenceException`（HTTP 500）。
- **可达性**：GoodsApply 尤其明显——表单未选申请人（EmpId 为空）即触发，属正常操作路径。
- **修复**：将守卫改为 `if (step == null || !ValidateBom(...))` / `if (worker == null || !ValidateBill(...))`。
  为 null 时直接进入校验失败分支，重绑表单并返回视图（200），不再解引用。
- **验证**：
  - POST `/GoodsApply/Create` 不带申请人 → `200` + 提示「请选择申请人！」（修复前 500）。
  - POST `/PmsBom/Create` 篡改 `StepId=999999` → `200` + 提示「工序不存在。」（修复前 500）。

## 审查通过项（无问题，记录备查）
- 鉴权：所有业务 action 均 `[Authorize]`，POST 均 `[ValidateAntiForgeryToken]`；Account 登录页无越权。
- 删除引用检查：SysDepartment（下级/用户）、SysUser（禁止自删）、SysRole（启用用户）、SysShop（关联用户）、
  PmsStep（BOM 引用）、PmsItemClass（子类别/商品）、SysMenu（子菜单）、DataDict（子项）均正确。
- 级联触发器表删除顺序：GoodsApply / StockBill / PmsProduceOrder 均「先删明细→再删头，分两次 SaveChanges」，
  规避 `tri_deletebilluse` / `GoodsApply_DEL` / `tri_deleteStockBillEntry` 级联 0 行报错。
- 树形结构防护：部门/分类/菜单均用 visited 防成环栈溢出，且禁止挂到自身/子孙。
- 单号生成：`JHD`/`CGRKD`/`SCD` 均为定宽 8 位零填充字符串比较，序正确（无跨 9→10 误判）。
- 视图 Razor：所有 `class="… @(…)"` / `@active` 均有空格分隔，无邮箱陷阱；无 `<option @(` 等独立表达式属性。

## 已知但非缺陷（按既有设计保留）
- 默认密码 `MD5("123")`：忠实兼容旧系统，弱口令属历史约定，未改。
- GoodsApply `FWorkShopID = vm.WorkShopId`（车间=部门 IsDEP==2）：新世界设计选择，与「旧 Workshop 字段作废」不冲突。
- StockBill/GoodsApply 未对 DeptId/ManagerId 做存在性校验（允许空），属数据质量项，不引发崩溃。
